# 文件传输助手公屏与手机授权

## 用户流程

文件传输助手是同一服务所有已授权用户共享的公屏。设备私聊继续使用独立的设备会话。

全新安装或清除应用数据后，打开文件助手会自动向服务器申请授权。服务器允许加入时，应用直接显示公屏；不需要另一台设备、连接码或 Tailscale。聊天页持续显示“公屏 · 本服务所有已授权用户可见”。

暂时无法联网时，页面显示原因并提供本机重试入口。服务器关闭新授权时，页面说明“服务器暂未开放公屏授权”，用户可稍后在手机上重新申请。聊天页右上角的“公屏与授权”可查看服务、重新申请或退出。退出后停止公屏同步，并可在同一入口重新加入。

旧安装已有的私人共享会话不会自动变成公屏。用户在设置中选择“公屏与授权 → 申请加入公屏”；原会话凭据和历史保留，可通过“返回原私人共享会话”恢复。同步按 conversationId 隔离，不重新发布旧会话内容。公屏成员不会自动成为可信私聊设备。

## 服务端协议

`POST /mpt/relay/v1/public-room/authorizations`，JSON 请求为 `{"deviceId":"phone-example"}`。

服务端返回 201，包含 `conversationId`、`token`、`grantId`、`name` 和 `visibility: service-public`。所有设备取得同一个公屏 ID，每次授权签发独立的随机凭据。应用包中不包含公屏共用密钥；授权响应禁止缓存，客户端沿用 MPT 的凭据存储。

服务端的 `MPT_RELAY_PUBLIC_ENROLLMENT` 环境变量控制申请策略：默认 `open`，其他值拒绝新申请并返回 403。当前为自动授权，并未实现账号登录或人工审批；关闭新授权不会撤销已有授权。

SQLite 的 `public_room` 保存服务级房间，`public_grants` 保存设备、授权 ID、凭据摘要及撤销标志。随机凭据只返回客户端，服务端保留 SHA-256 摘要。每次公屏请求都检查授权状态；管理员可对指定 grantId 调用 `Store.revoke_public_grant`，撤销立即影响后续请求。开放申请期间，设备仍可再次申请新授权，因此单次凭据撤销不等同于设备封禁。

原有私人命名空间仍使用原来的鉴权方式，公屏凭据不能访问私人命名空间，也不能用来配对设备。公屏连接码导出被禁用，界面引导用户在每台设备独立申请。

公屏当前复用共享 WebDAV 消息协议；获授权的成员具有该共享空间的读写能力，尚无逐条消息的所有者权限。新的公屏授权没有复制到独立 Tail 中转服务，公屏文件使用公网中转或已有网盘路径；私聊的已有直连与中转行为保留。

## 验收

自动化覆盖真实 Python 中转服务下两个 .NET 模块自动加入、消息接收、退出/重入；覆盖公屏凭据互通、单份授权撤销、关闭申请、私人空间隔离，以及 390/1000 宽度的手机授权入口。新增迁移回归验证旧私人消息不发布到公屏，且可以恢复原会话。

Pixel 4a（Android 13）使用独立包 `com.mypowertools.publicqa` 模拟全新安装，保留原应用数据。已观察到自动加入、公屏可见性提示、手机发出测试消息被独立授权端读取，以及手机显示独立端回发的消息。退出后可在同一手机点击“申请加入公屏”恢复授权和公屏会话。验收不把 HTTP 成功或编译成功当作手机 UI 通过。

本次 Android 版本为 0.2.13（versionCode 15）。Windows 仅通过隐藏的 Tools Dev overlay 更新，不唤起用户桌面窗口。macOS 本次未做真机验收。
