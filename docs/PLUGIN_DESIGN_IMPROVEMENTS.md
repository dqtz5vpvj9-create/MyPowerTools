# 插件设计改进方案

审查日期：2026-08-19  
视角：从用户看到和操作的实际 UI 出发，识别设计上的粗糙之处和改进方向

---

## 跨插件设计问题

### 1. 设计语言不统一

8 个插件在视觉上是三个不同的世界：

- **第一阵营（MPT 设计系统）**：ADB Forwarder、ScreenEase、Remote Notifications、Doubao、SmartBird——用 `MptBrush*`/`MptRadius*`/`MptSpacing*` 令牌，外观与 Shell 一致
- **第二阵营（自建样式）**：Input Monitor——完全独立的颜色系统（`#F4F6F9` 背景、`White` 卡片、`#0A85FF` 强调色、`#6B7280` 次级文字），与 MPT 设计系统零重叠
- **第三阵营（裸 Avalonia）**：Paste Image——硬编码浅色值（`#D8D8D8` 边框、`#666666` 文本、`#EFF6FC` hero），连 `accent` 按钮类都自定义

**改进**：Input Monitor 和 Paste Image 需要迁移到 MPT 设计系统。不是逐行换颜色值的问题——需要重新用 `MptBrushCardBackground`、`MptBrushBorder`、`MptBrushTextSecondary` 等令牌重写样式定义。这同时解决暗色主题问题。

### 2. 信息层级不一致

有的插件 hero 区太重、内容区太轻（Paste Image 的蓝色横幅占了首屏一半空间但只传达了一句话），有的没有 hero 直接跳内容（Remote Commands）。没有统一的页面结构约定。

**改进**：建议所有插件遵循一个松散的页面结构：`标题行 → 状态/操作条 → 主内容区`。SDK 的 `component-contracts.md` 已定义了 `MptModuleHeader`（title + state + actions）但没有强制使用。

## 逐工具设计改进

### Remote Notifications

**当前设计的优点**：标签过滤芯片条是好设计——比下拉框更快、更可发现。卡片布局信息密度适中。连接状态折叠在 Expander 里是正确的——大多数时间用户不需要看它。

**需要改进的地方**：

1. **卡片缺少已读/未读的视觉区分**——所有卡片看起来一模一样。通知收件箱的核心体验是"扫一眼就知道有什么新的"。建议：未读卡片标题用 SemiBold + 左边条着色（参考 Outlook/Teams 的未读样式），已读卡片标题用 Normal。不需要额外按钮——打开即标读。

2. **状态指示器用 ViewModel 里的 hex 字符串绑定颜色**（`StatusBackground`/`StatusForeground`）——这是反模式。Avalonia 样式系统有 `Classes.running`/`Classes.error` 的方式（SmartBird 和 Shell 里已经在用），应该改成样式类驱动，而不是在 ViewModel 里算颜色值。

3. **右键菜单只有一个"复制"**——对比 Shell 的 Command Palette 右键菜单的丰富度，这个太寒酸了。至少加"打开""删除""复制会话 ID"。

4. **设置面板的"test connection"结果用绿/红文字反馈**——但颜色也是硬编码 hex。应该走 `MptBrushSuccess`/`MptBrushDanger`。

### ScreenEase

**当前设计的优点**：三档响应式布局是全部插件中最好的。侧栏选中态的 4px 强调色竖条清晰优雅。自定义滑块模板（20px 圆形 thumb + 细轨道）手感好。整个页面用了专属 `MptBrushScreenEaseAccent` 建立了工具的品牌感。

**需要改进的地方**：

1. **"高级"展开器里的内容太重要了**——平滑过渡、遮罩、快捷键——这些不是高级功能，是日常功能。把遮罩和快捷键提到主区域，只有 CareUEyes 导入才算真正的"高级"。

2. **番茄钟和显示调节在同一个视图里争夺注意力**——这是两个完全不同的用户意图（"调节屏幕"vs"管理工作节奏"），目前它们在同一层级同一行并排。建议：主视图以显示调节为核心，番茄钟移到一个单独的标签页或折叠面板。

3. **配置文件侧栏的"保存"和"新增"按钮视觉权重相同**——两个操作的后果完全不同（覆盖 vs 新建），但看起来一样。"保存"应该是 primary 样式（accent 填充），"新增"应该是 secondary（边框）。

4. **夜间值编辑模式用三个复选框控制**——"启用夜间值""编辑夜间值""按时间自动切换"。三层嵌套关系不直观。建议改为一个 toggle group 或者更线性的流程：启用夜间→设日出日落→编辑夜间值。

### ADB Forwarder

**当前设计的优点**：双表格布局（有线/Wi-Fi）清晰地分隔了两种设备类型。脏状态追踪（"配置需要保存"/"配置已保存"）做得好。设备状态用颜色点+文字双编码信息，不依赖颜色单一通道。

**需要改进的地方**：

1. **仪表盘 vs 设置 vs 诊断的导航方式不一致**——设置和诊断通过标题栏按钮切换，但切换后没有明确的返回路径，也没有标签页提示当前在哪个视图。建议改为 TabControl 或显式的面包屑导航。

2. **设备表格在无设备时的空状态太简单**——只有一行灰色文字。对于需要配置才有设备的工具，空状态应该包含行动指引："添加第一个有线设备"按钮直接导航到设置页。

3. **Wi-Fi 设备行有 6 个文本输入横排**——在窄窗口下严重挤压。每行改为卡片式（名称+关键信息在首行，详细字段折叠在二级区域）会更健壮。

### Paste Image

**当前设计的优点**：hero 横幅传达了完整的工作流概念（复制→上传→粘贴），快捷键徽章在右上角很醒目。反馈横幅的颜色编码（蓝/绿/红 + 图标）能有效传达操作结果。

**需要改进的地方**：

1. **整个页面没有使用任何 MPT 设计令牌**——这是 8 个插件中唯一完全脱离设计系统的。`Border.card` 用 `#D8D8D8`、`.secondary` 用 `#666666`、hero 用 `#EFF6FC`——全是浅色硬编码。重写为 `MptBrushBorder`/`MptBrushTextSecondary`/`MptBrushInfoBackground` 是基础要求。

2. **反馈横幅的颜色也从 ViewModel 绑定 hex 值**（`MessageBackground`/`MessageForeground`）——和 Remote Notifications 的状态指示器同一个问题。应该改为 severity 样式类驱动。

3. **上传按钮用了自定义 `accent` 类**而不是 `MptPrimaryButton`——造成按钮外观与其他插件不一致。

4. **历史记录行是纯文本显示，无交互**——远端路径不能复制是最大的日常摩擦点。每行加一个复制图标按钮即可。

5. **"可在 Paste Image 设置中修改"这句话在页面最底部**——首次使用时用户根本不知道从哪里改配置。建议在上传目标卡片上加一个"修改"链接按钮，直接导航到设置。

### 豆包 Computer Use

**当前设计的优点**：运行时状态卡片的 7 态状态机设计完善——每种状态都有明确的文本和行动按钮。凭证区在未配置时自动展开是好的首次运行引导。活动仪表盘的 4 个指标磁贴 + 截图预览 + 追踪列表提供了丰富的运行时洞察。

**需要改进的地方**：

1. **截图预览区太小（固定 280px），且和遮罩调试控件混在一起**——视觉代理的核心价值是"看到 agent 在做什么"，但这个价值被一个邮票大小的缩略图和几个 X/Y/radius 数字输入框淹没了。建议：截图预览占据右栏的主体空间，可点击放大；遮罩调试折叠到诊断区。

2. **"Grounding"指标磁贴没有解释**——这是一个 VLM 领域的专业术语，在上下文中指代理对屏幕元素的定位准确率。需要一个 tooltip："基于元素定位的操作精度"。

3. **任务面板的模型下拉列表只显示模型 ID**（如 `doubao-1.5-thinking-pro-250415`）——技术细节对普通用户无意义。建议在下拉项里显示友好名称 + 模型 ID 副文本。

4. **进程/端口表格暴露了过多内部细节**——PID、端口号、状态码这些信息对终端用户价值很低但占据了大量空间。建议默认折叠，只在"诊断"展开器里显示。

### SmartBird Thermostat

**当前设计的优点**：标题栏用芯片条显示模式/制冷/温度/设备数——信息密度高且扫描友好。在线/离线用绿/橙圆角徽章区分清晰。设置区的 5 个配置分组有逻辑层次。

**需要改进的地方**：

1. **WebView2 回退卡片信息密度为零**——浏览器引擎不可用时用户看到一个"SB"字母图标和三个按钮，没有任何温度/状态数据。但 `SmartBirdThermostatSnapshot` 里有这些数据，只是没有渲染。建议：回退视图用原生 Avalonia 控件渲染一个简洁的温度仪表盘——大号表面温度、露点、环境温湿度、制冷状态开关。这比修好 WebView2 优先级更高，因为它保证了工具在任何环境下都有用。

2. **设置页和控制台互斥**——调参数时看不到当前读数，保存会重启服务导致数据断流。建议改为分栏或叠加面板，让核心读数始终可见。

3. **`IsStale`/`StalenessWarning` 属性已在 ViewModel 中计算好但从未渲染**——这是上一轮发现的"幽灵代码"。标题栏的芯片条旁加一个警告徽章绑定 `IsStale` 即可（改动约 5 行 AXAML）。

### Input Monitor

**当前设计的优点**：图表系统很丰富——7 种可视化覆盖了时间、频率、空间（热力图）、分类（应用）多个维度。粒度/维度/分类三级过滤器组合灵活。自定义 DrawingContext 渲染的图表风格统一。

**需要改进的地方**：

1. **完全自建的颜色系统是最大的设计问题**——`Background="#F4F6F9"`、`Background="White"`、`Foreground="#6B7280"`——这 60+ 个硬编码值让这个插件在暗色模式下完全不可用（刺眼的白色矩形），也与其他插件格格不入。修复不是逐值替换——需要把 `DashboardPalette` 改为从 Avalonia 主题资源读取，把所有样式定义从硬编码改为 `{DynamicResource MptBrush*}`。

2. **标题栏太拥挤**——疲劳值、前台应用名、采集状态三段灰色 13px 文字挤在左侧；三个按钮挤在右侧。没有层级区分——全是同色同号。建议：疲劳值用专色（如达到阈值时变为 Warning 色）和更大字号凸显；前台应用名降为 tooltip 或可展开区域；按钮用图标+文字而非纯文字。

3. **四张汇总卡片的图标是硬编码的彩色方块**——`Background="#0A85FF"` 上放一个"键"字。设计系统有 `MptBrushAccent`，用它加上图标字体会更统一，且自适应主题。

4. **分段选择器（日/月/季/年、全部/键盘/鼠标/应用）用自建按钮样式**——有 `.seg` 和 `.seg.selected` 类但不用 MPT 的 `MptTabStrip` 或类似组件。视觉上与 Shell 风格断裂。

### Local Lag Cleaner

**当前设计的优点**：两阶段安全确认（8 位令牌 + 条件复选框）是同类工具中罕见的审慎设计。12 个指标卡片的 4 列均匀网格 + 8 诊断域的分组展示，信息密度和可扫描性都好。严重度徽章用颜色编码有效传达优先级。

**需要改进的地方**：

1. **三个选项卡（总览/证据/清理）的关系不直观**——用户的心智模型是"扫描→看结果→采取行动"，但当前的标签名（"总览""证据&进程""处置计划"）太技术化。建议改为"诊断结果""详细数据""修复操作"。

2. **6 个硬编码的清理计划按钮与诊断结果之间没有任何视觉关联**——用户做完扫描后看到"NVIDIA Container"按钮，不知道这跟自己的卡顿有没有关系。建议：扫描结果出来后，高亮/推荐与发现匹配的计划按钮，灰掉无关的。

3. **进度指示太弱**——不确定进度条 + 状态文本。扫描时长已知（5s/15s），应该用确定进度条。

4. **报告路径在页面底部显示为裸文件路径**——无"打开"按钮。加一个 `MptButton`（Content="打开报告"）+ 一个复制路径按钮。

### Remote Commands

**当前设计的优点**：工作区 + 历史面板的分栏布局是 IDE 风格，对目标用户（开发者）很熟悉。历史搜索和双击恢复流程设计得好。

**需要改进的地方**：

1. **工具栏是最大的设计问题**——11 列 Grid 横排了标签+下拉+标签+输入+7 个按钮。没有任何分组或层级——主操作（Run）和次操作（Copy/Clear）视觉权重完全相同。建议分两行：第一行放命令选择+主机+Run/Cancel（核心流程），第二行放 Copy/Clear/Edit/Settings（辅助操作），用分隔符或背景色区分。

2. **"Input 1"和"2nd input"标签完全不说明输入是什么**——每个命令期望的输入不同，但界面对所有命令都显示同样的泛化标签。建议在命令定义的 YAML schema 里加 `input1Label`/`input2Label` 字段，UI 动态显示。

3. **输出区没有任何运行中指示**——命令执行期间只有 Run 按钮变灰和状态栏文字"Running..."。输出区的 `PlaceholderText="Output will appear here..."` 保持不变直到第一行输出到达。建议在 `IsRunning` 期间显示一个小 spinner 或脉冲动画在输出区。

4. **历史面板固定 320px 且不可调整**——大输出时用户希望历史窄一点给工作区更多空间。建议加 SplitView 或可拖拽分割条。

## 优先级总结

### 立即可做（5-20 行 AXAML 改动）

| 改动 | 工具 | 效果 |
|------|------|------|
| 绑定 `IsStale`/`StalenessWarning` | SmartBird | 过期数据不再伪装成实时 |
| 历史记录行加复制按钮 | Paste Image | 日常最频繁操作不再缺入口 |
| 卡片标题 SemiBold/Normal 区分未读/已读 | Remote Notifications | 收件箱核心体验成立 |
| 扫描进度条改为确定式 | Lag Cleaner | 5s/15s 已知时长不该用不确定进度条 |
| "保存"用 MptPrimaryButton、"新增"用 secondary | ScreenEase | 操作权重视觉区分 |

### 中期改动（需重写样式或布局）

| 改动 | 工具 | 效果 |
|------|------|------|
| 迁移到 MPT 设计系统 | Input Monitor | 解决暗色主题 + 视觉统一 |
| 迁移到 MPT 设计系统 | Paste Image | 同上 |
| 工具栏分两行+按命令动态标签 | Remote Commands | 窄窗口可用 + 输入有引导 |
| WebView2 回退渲染原生温度仪表盘 | SmartBird | 无浏览器引擎时工具不再是空壳 |
| 截图预览区放大 + 遮罩调试折叠 | Doubao | 视觉代理核心价值充分展现 |
| 清理计划按钮与诊断结果关联高亮 | Lag Cleaner | 诊断→行动的流程闭环 |
