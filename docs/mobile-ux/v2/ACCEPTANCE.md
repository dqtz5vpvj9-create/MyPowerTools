# 端到端验收清单

这份表的初始状态全部为“未验收”。0.2.2 的局部结果不自动继承为 V2 通过。每次运行记录构建版本、设备/系统、配置来源、实际动作、对端结果和截图。截图必须亲自看；自动化树坐标不能代替滚动后的实际画面。

## 环境与执行方法

- 一组干净独立配置验证首次使用，一组保留历史的升级配置验证迁移。不能清空用户真实数据；专用测试设备可使用独立配置或经备份的测试实例。
- 至少 Windows 开发版 ↔ Android 实体设备或专用 AVD 双端。AVD、实体手机、macOS 结果分别记录。
- 手机用真实界面选择、扫码/粘贴、发送、打开、返回。电脑也由真实 UI 完成配对和收件查找。后台命令只读核验落盘，不替代用户操作。
- 联网用例测试默认公网；另设已有 Tailnet 可达路径、无 Tailnet 路径、对方离线、本机离线。不能由本机是否有 100.x 网卡推断两端连通性。
- 每个动作后保存新画面，尤其输入法、系统选择器、查看器和权限对话框切换。敏感连接码不进入公开截图或日志。
- 失败就记录发生在哪一步，不能补后台命令让流程“通过”，不能以截图里有成功条目证明本次操作成功。

## 结果登记格式

每个 ID 记录：构建提交；手机型号/系统或 AVD；电脑系统；首次/升级配置；网络条件；逐步 UI 动作；实际结果；截图/日志路径；通过/失败；未覆盖项。端到端通过必须包括发送方和接收方，不能只测客户端命令返回成功。

用户要求发布后邮件通知。仅在对应发布范围通过并且实际下载可用后发送邮件，包含版本、链接、具体完成范围与已知未覆盖项。不得再次把局部验收包装成整个手机版完成。
