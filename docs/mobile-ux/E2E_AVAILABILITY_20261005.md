# Android 真机 e2e 验证记录

本页保留首轮结果；后续手机发送、草稿、后台恢复及画面检查见 [追加验证](E2E_FOLLOWUP_20261005.md)。

框架：[tester-army/e2e](https://github.com/tester-army/e2e)。固定版本：e2e 0.16.0、@e2e-dev/mobile 0.9.2、agent-device 0.21.20。

## 设备与版本

用户指定的两台 Pixel 4a 已经按硬件序列号核对：08111JEC207803 对应 10.33.0.145:15558；08191JEC213478 对应 10.33.0.145:15557。两台均支持 root，测试没有清除应用数据，也没有操作 Windows 桌面。

08111 最初运行已发布 0.2.9/code11（43ad044），随后升级为当前源码的 Android QA 开发包；08191 使用当前源码开发包。当前构建以 81a4240 为基础，仅含本轮测试脚本调整，版本仍为 0.2.9/code11，不是新正式发布。通过 scripts/build-android.ps1 构建，Android 规则测试 103/103 通过。

## 发现与修复

**当前不能认定手机高可用验收通过。**

1. 无障碍点击路径失败：两台手机的首页控件边界与实际图像存在约 136 像素纵向差异。08111 的已发布包和 08191 的当前开发包都复现；前台 Activity 始终属于 MPT。已查看失败截图。补偿坐标能进入聊天，但不代表该问题已修复；尚未确认责任在应用、Avalonia 还是驱动。
2. 新会话无法开始中转：独立生产对端看到 HTTP 429，消息保持 queued。源码曾默认每个来源每小时 5 次创建、全服 100 次；线上实际按来源配置 20 次。此规则不是用户要求。同一代理出口共享配额会影响设备接入。现在两个创建频率限制默认关闭，线上也已更新为 0；密钥认证、认证失败窗口、容量及命名空间总量上限保留。显式非零运维配置仍可启用限频。中转测试 238/238 通过，新会话已在手机收到消息并产生该手机回执。
3. 测试设施修正：需要共享同一生产对端实例的用例放入串行组；连接确认在二维码下方，先滚动到确认按钮；输入框按 Android 实际暴露的 textbox 名称定位。早期测试生命周期或错误选择器造成的失败，不计作产品故障。
4. 附件菜单的两个按钮暴露为 `Avalonia.Controls.Grid`，不是文件/照片名称。诊断脚本改按可见的“从设备选择文件”文本点击；这是绕过无障碍命名缺失，不是修复。
5. 输入路径仍受阻：修正选择器后，Android 驱动 fill 返回校验失败。尚未证明普通用户的软键盘输入失败，不能直接归因到业务发送。正常模式继续保留该检查，诊断模式可单独执行不依赖 fill 的传输场景。

旧的 10.33.0.155:5555 与 10.33.0.156:5555 测试受到其他阅读应用自动化抢占，仅属无效尝试，不计产品失败。

## 有效执行结果

08191 当前开发包，专用会话，`.e2e/mobile-08191-transport-final`：**5/5 通过**，耗时 122.69 秒。此轮启用了坐标补偿，并未收集三个依赖输入驱动的用例。

| 场景 | 证据及结果 |
| --- | --- |
| 连接并接收真实中转消息 | 手机保存消息；对端收到该手机 deviceId 的接收回执 |
| 取消 Android 系统文件选择器 | 确认 DocumentsUI 是前台后返回，编辑栏恢复、消息数不变 |
| 同名文件 | 两份不同内容逐字节核对、保存路径互异、完成字节数等于文件大小 |
| 删除测试缓存后重收 | UI 点击重新下载，恢复相同内容，保持同一消息 id，无新增消息 |
| 应用 IPv4 断网后恢复 | 阻断期间无该手机回执；解除后自动收到回执；finally 恢复规则，测试结束核对无残留 |

无补偿的当前包首页语义点击 **1 项失败**。正常套件在输入驱动 fill 校验失败后跳过余下 6 项；不将这些跳过计作失败或通过。草稿、五轮后台恢复及手机 UI 发送尚未完成有效验收。

## 闲置 CPU

08111 当前源码 QA 包，首页保持前台，正常接收服务保持启用；预热 30 秒后测量 123.49 秒。通过 root 读取 MPT 及其子进程的 /proc CPU ticks，PID 集合在窗口内保持稳定，平均合计为单核的 0.194%。原始数据为 08111-idle-cpu.json。这次结果仅覆盖前台首页闲置，没有测量锁屏后台、系统唤醒或电池续航。

## 可复现运行

完整套件会确认加入专用测试会话。只能使用专用手机、专用会话凭据，不能接入日用共享会话。

```sh
npm ci --ignore-scripts
/home/chris/.dotnet/dotnet build tests/e2e/MobilePeer/MobilePeer.csproj
MPT_E2E_SERIAL=10.33.0.145:15557 E2E_TELEMETRY_DISABLED=1 \
  TMPDIR=/mnt/cache/data-cache npm run test:mobile
```

MPT_DOTNET 可以覆盖 dotnet 路径。MPT_E2E_INVITATION_FILE 指向本地私有测试连接码文件：首轮写入，之后复用，避免污染生产命名空间；不提交文件及连接凭据。对端使用生产模块和正常公网中转，没有模拟传输。

MPT_E2E_TOUCH_OFFSET_Y=136 仅补偿诊断点击；首页语义点击用例始终不补偿。MPT_E2E_TRANSPORT_ONLY=1 不收集手机输入、草稿及含输入操作的恢复用例，这些不能算作通过。其余传输测试仍使用 UI 与真实收发回执。

MPT_E2E_NETWORK_FAULTS=1 要求专用 root 手机，只阻断应用 UID 的 IPv4 出站，在 finally 恢复唯一命名规则；不关闭 TCP ADB 使用的 Wi-Fi。未执行时不能声称断网恢复通过；IPv6 尚未覆盖。

原始报告保留在忽略提交的 .e2e/mobile-08111-initial、.e2e/mobile-08191-current-semantic、.e2e/mobile-08191-current-diagnostic、.e2e/mobile-08191-dedicated-diagnostic、.e2e/mobile-08191-native-selectors、.e2e/mobile-08191-transport-isolated 和 .e2e/mobile-08191-transport-final。记录包含截图、控件树和回执检查；凭据与设备通知不导出 GitHub。构建、服务器测试和 CPU 原始数据位于 /mnt/cache/data-cache/mpt-mobile-e2e-20261005。

## 验收边界

上述五项仅在诊断补偿模式通过。私聊与共享隔离、用户保存副本时扩展名前的重名后缀、接收失败文案、中途取消或进程死亡、大文件、真实夸克/百度授权失效及配额、锁屏省电模式仍需独立真机覆盖。接收通过、源码测试通过、服务 health 返回 200 均不能替代这些场景。
