# Android 0.2.2 开发预览验收

本次修正文件助手对本机 Tailscale 网卡的依赖，并接入默认公网中转。设备身份和连接码在本地生成；对端的候选地址只参与路径选择。普通配对只授予文件投递权限，加入自己的共享会话仍使用独立的确认流程。

## 已验证的行为

2026-09-28，专用 Android AVD `mpt-android-preview`（0.2.2，versionCode 4）与 Windows 官方开发版进行了实际互传。两端均没有本地 Tailnet 地址，传输通过 `https://proxy.lixinrui000.cn` 的设备收件箱完成。

- 双方导入普通配对码后，文字与附件均可双向发送。收件端实际保存文件，发送端收到保存回执后显示送达。
- Android 停止接收时，Windows 发送的内容保持“已暂存”；恢复接收后自动保存并回执，过程中没有手动同步或重试。
- Android 可以用系统查看器打开收到的文本附件；只为对应内容 URI 授予读取权限。
- 系统分享的文字和附件进入待发送区，不自动发送。三次冷启动的中文字体与图标检查通过。
- Windows 官方 Core 和 file-transfer Tools Dev 更新均已完成并启动。已修复的 Input Monitor 组件保持不变。

三个跳过项为既有 Android 数据面夹具和两个需要独立 OpenList 环境的集成用例，不计作通过。

## 设备 UI 复核

最终包于同一专用 AVD 保留数据覆盖安装后复核通过：进入会话时最新记录可见；自己发送，以及 Windows 在会话打开期间发来的文字和附件，都无需滚动或切页即可看到。已有内容显示“已接收”。主代理查看了对应截图。

二维码在前一轮已实际解码成功，确认无遮挡。外部查看器返回流程连续验证两次：打开附件、返回后立即点击“设备”或“工具”，均进入对应页面，之前的触摸失效未在这两次复验中出现。此结论限于该设备和复验次数。

初次复核中的“最新消息超出可滚动范围”判断已纠正：截图证明手动滚动能看到记录，实际缺陷是自动底部跟随时机。修复依据布局变化进行滚动，未修改传输数据。
