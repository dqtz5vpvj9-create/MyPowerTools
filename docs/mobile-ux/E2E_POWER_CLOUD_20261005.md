# 网盘分享与后台恢复修复验收

日期：2026-10-05。范围为文件传输可用性；未调整页面外观。使用 tester-army/e2e（e2e 0.16.0、@e2e-dev/mobile 0.9.2）和用户指定的两台 Pixel 4a / Android 13：08191JEC213478、08111JEC207803。测试使用专用 QA 会话，不接入日用聊天。

## 实现

- 接收模式持有 Android 前台服务，不再把前台服务的生存期绑定到本地/Tailnet 监听是否成功。用户停止接收仍释放服务。
- 主机通过 `network.recovery` / `IObservable<bool>` 通知插件网络恢复和 Doze 退出。插件取消旧连接并唤醒持久队列。BCL 接口可以跨插件加载上下文；没有依赖分离程序集中的静态事件，也没有新增轮询或唤醒锁。
- 文件复制按 60 秒无进展判断停滞，而非按整个文件总时长终止。取消仍保留取消语义，重试通过临时文件和原子提交避免留下伪完成文件。本次没有实现 HTTP Range 续传，失败文件仍从头重试。
- OpenList 上传与旧网盘流转发取消固定的总时长上限，管理请求仍有独立时限。
- 夸克发送方使用已有账号创建单文件分享，接收方通过匿名访问下载。会话中仅存分享凭据，不传发送方 Cookie。分享元数据先于消息发布；旧客户端仍有原流转发路径。新功能用于新发送/重试发布的附件，未回填旧消息。
- 夸克匿名客户端单独保存网盘签发的访客 Cookie，否则真实 CDN 返回 412；它与账号客户端完全分开。分享有效期为七天，会话领取期限不超过该期限。
- WebDAV 读取增加 30 秒响应头等待预算。单个附件丢失、过期或下载停滞不会再中止整批接收和回执；认证拒绝、限流及连接错误仍保留整体退避；目录发现等控制请求的服务器故障也继续退避。单文件 503 可能只是发送方尚未提供文件，不再据此判定整个服务故障。
- 多设备回执每轮最多查 12 条，但现在会用一次更新对应的固定水位分批查完；全部查完后回到事件等待。此前历史消息较多时，一台设备的回执已到，第二台的回执可能永远漏刷新。水位从持久记录恢复并单调推进，不增加永久轮询。
- inspect 读取加锁后的完整快照，避免重试时把前后两次状态拼成矛盾结果。

## 验收记录

Core 最终全量 389 项：386 通过、0 失败、3 项原有外部 fixture 测试跳过，耗时 3.00 分钟；Android 主机规则测试 103/103 通过。Core 在独立网络命名空间中运行，避免测试固定端口与现有 OpenList 服务碰撞，没有停止用户服务。日志 `core-receipt-manual-final-netns.log`、`android-queue-fix-build.log`（Android 主机代码此后未改）。

新增队列测试覆盖 404、410、单文件 503、响应头无限等待后的继续下载和真实回执；401、403、429 及真正连接拒绝仍退避。持续进展测试明确要求整个文件传输时间超过一个空闲窗口，不能把固定总时长限制误当作空闲超时。

### 真机回归结果（注明构建阶段）

队列修复包、回执分批修复前，08191 的后台恢复套件 **4/4 通过**，总耗时 128.24 秒，报告 `.e2e/mobile-power-queue`，日志 `power-queue.log`。

| 场景 | 接收证据 |
| --- | --- |
| Home 后后台接收 | 发布后约 2.17 秒收到文件 |
| 锁屏接收 | 发布后约 1.10 秒收到，接收后屏幕仍不交互 |
| 强制 Doze | 此设备在强制 Doze 内已收到；退出后的 58ms 检查不是恢复延迟 |
| 强制 Doze + 应用 UID IPv4 DROP | DROP 期间未收到；删规则并退出 Doze 后约 3.17 秒收到，屏幕仍不交互 |

四项均逐字节核对文件、消息仅一条、完成字节数准确，且发送端读到指定手机的持久回执后才通过。未打开 Activity 来触发接收，也未加 Doze 白名单。此结果不保证所有厂商或无限期深度休眠下实时送达。

夸克已使用设备原有登录完成真实测试文件上传、创建分享和原生客户端匿名下载，1,605,632 字节逐字节相同。08191 在发送进程退出、手机无网盘账号的条件下，收到同一份真实分享文件，链路标记 `cloud-quark`，字节内容一致，测试 1/1 通过。最终 APK 在 08111 上同样通过 1/1 独立分享测试（`.e2e/mobile-quark-share-queue` / `share-queue.log`），发送进程真实退出后才启动接收应用，接收手机账号列表为空。手机测试通过测试命令发布真实分享描述符，不代表手机上传界面验收。另已使用真实生产 FileTransferModule 完成独立全链路：复用原夸克授权，真实挂载并读写，assistant.send 上传 1 MiB，经 PublishCloudAttachmentAsync 自动解析路径、创建分享及持久化，然后退出发送模块；全新无网盘账号模块通过会话元数据领取并直接从夸克下载，逐字节相同，route=cloud-quark。证据 `quark-module-live-evidence.json`。隔离网络命名空间与临时 slirp 用于避开原 OpenList 15244 端口；原服务未停。

队列修复后，08111 又复现“已收件且已写回执，但发送端没有刷新到该手机”的失败。peer 在一次更新中只轮询 12 条历史消息便休眠，目标消息已经有另一台手机回执，因此后来的回执被遗漏。随后增加固定水位分批扫描，新增 25 条历史、A 已确认、B 新回执的单次更新回归，并验证扫完后不空转。

中间版本曾出现 3/4 后台测试通过：Doze+断网后手机已完整收件，但发送端回执检查超时，此次整体不通过。第二台手机的旧附件阻塞及一次测试 peer 提前退出也保留为失败记录；没有用收到文件掩盖回执失败。修复队列和响应头时限后重新回归。

初次增量 APK 构建未刷新插件嵌入目录，导致新 Core 和旧插件混装。该次失败不计通过。随后改用完整 `scripts/build-android.ps1`，核对 APK 内的 Core/插件 DLL 与本轮暂存产物一致，再安装测试。当前为 0.2.9/code11 开发包，并非正式发布。

## 百度边界

已有百度 OAuth 登录仍有效，两份历史 QA 授权的用户信息接口均 HTTP 200 / errno 0。本次没有要求用户重新登录。

当前 OpenList 托管 OAuth 没有独立分享服务 appid/权限。百度官方[创建分享链接文档](https://pan.baidu.com/union/doc/基础网盘服务/文件分享服务新/创建分享链接/)要求开通分享服务及相应权限；[分享下载文档](https://pan.baidu.com/union/doc/基础网盘服务/文件分享服务新/获取分享下载地址/)要求 access_token，并明确禁止非登录下载。因此当前官方授权路径尚未实现“发送方离线、接收方不登录”的百度分享下载。保留原有发送方在线转发，不把账号登录成功当作独立分享下载通过。
