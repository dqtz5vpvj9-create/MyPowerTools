# 文件助手用户流程验收

每次修改文件助手后，开发者负责操作应用并观察结果。编译、接口测试和发送端显示成功不能代替接收端验收。用隔离测试会话及测试文件，保留用户正在使用的聊天、账号和桌面。

Windows 的构建与测试脚本必须隐藏运行。界面自动化使用隔离环境，不抢占日用桌面的焦点，也不重启用户正在使用的窗口。

## 实际操作

| 场景 | 操作 | 应看到的结果 |
|---|---|---|
| 文字 | 发送中文、空格、emoji 和多行文字 | 接收端内容一致，emoji 正常显示；回执属于实际接收设备 |
| 文件 | 发送照片、PDF、多文件及大文件 | 接收端文件完整且能由系统应用打开，发送端收到真实回执 |
| 通讯录 | 打开设备名片，进入私聊，再进入文件传输助手 | 私聊只显示该设备的消息，共享消息只进入共享会话 |
| 草稿 | 两个聊天各写草稿、添加附件，反复切换 | 每个聊天保留自己的草稿；正在发送的回调不清除另一聊天内容 |
| 系统选择器 | 打开附件选择器并取消，再正常选择文件 | 取消不产生消息或附件；选择后先成为草稿，由用户点发送 |
| 系统分享 | 从其他应用分享文字或文件到 MPT | 用户能确认接收会话和内容；返回、取消、重复进入不自动重复发送 |
| 打开与返回 | 打开收到的文件，选择查看器，再返回 | 查看器能读取内容；返回原会话，无权限错误或空白页 |
| 同名文件 | 收到两份内容不同的同名 PDF，分别保存副本 | 两份均保留，文件名为 `report.pdf`、`report (1).pdf`，都能打开 |
| 删除后重取 | 删除收到的本地文件，点原消息或重新下载 | 从原消息恢复，沿用原消息 ID；失败时明确显示接收失败并允许重试 |
| 中断与重试 | 下载中断、服务报错、恢复后重试 | 不把部分文件当作已接收；接收端不显示发送失败；重试确实重新执行 |
| 取消 | 发送、接收和手动重新下载中取消 | 网络操作中止，状态与实际结果一致；不会随后把已取消任务写成成功 |
| 状态反馈 | 出错后切换聊天 | 另一聊天不显示原聊天的错误；提示不暴露内部路径或堆栈 |
| 后台与重启 | 退到桌面接收，再恢复窗口；有任务时重启应用 | 消息和文件不丢失，状态恢复一致；重新连接不重复生成消息 |
| 分享后的生命周期 | 从文件管理器分享并发送，退到桌面，再接收新消息；至少重复三次恢复 | 每次都恢复历史和输入框；后台回执正常也不能掩盖黑屏或不可交互 |
| 链路 | 分别通过直连、Tailnet 中转、公网中转、网盘传输 | 接收进度旁显示实际链路，自动回退后同步更新，无需用户选择网络 |
| 云端异常 | 模拟授权失效、配额不足及下载链接失效 | 不假报成功，不丢失已经入队的消息；给出可执行的恢复入口 |
| 闲置 | 无交互、等待消息、等待回执时测量 | 保留已启用的接收服务；无文件系统忙等、无无关目录监视 |

## 判定与记录

每项记录使用的版本、操作步骤、预期与实际结果、失败复现和修复后结果。截图必须实际查看；保存副本要检查系统目录中的真实名称，而不只检查聊天气泡。失败路径应以真实 HTTP 请求或故障注入验证，不能用直接修改状态代替。

分别标明真机操作、后台网络测试和界面组件测试。未测的链路、平台及权限条件留作未验收，不能用其他平台的通过结果替代。纯直传且没有任何远端副本的消息，在本地文件被删除后需要发送端可用及取回协议；这类限制必须单独记录。

发现用户流程阻断问题后，修复并在同一设备上重复原操作，再继续验收。待验收包不能因为单元测试或发送回执通过而发布为可用版本。
