# 我的网盘：产品接入与验收

依据 `.lavish/mpt-cloud-v4/README.md` 的交互原型实现。用户在会话设置打开「我的网盘」，添加账号后回到原会话，草稿、附件、聊天历史和当前接收任务继续保留。

## 普通用户流程

1. 首次进入显示添加网盘入口及用途。已添加时显示品牌、账号名、真实状态、存放位置和默认标识。
2. 选择品牌后启动该品牌实际支持的授权方式。手机提供同机入口；没有可用同机授权时明确说明条件，不展示模拟二维码或假登录成功。
3. 授权返回后准备专用目录，完成真实读写确认后显示可用。取消、失败或切页不能覆盖原有账号。
4. 回到聊天继续发送。无需手动启动 OpenList、填写端口、管理员密码或 DAV 路径。已有手动配置保留在高级设置。
5. 登录过期可重新授权并保留目录与策略。空间不足只能根据提供方实际错误或容量信息显示；容量未知时如实展示。

## 管理操作

目录通过浏览选择，修改仅影响后续发送。默认账号只能选实际可用且未暂停的账号。暂停保留登录与任务；断开移除本机凭据，保留网盘文件，提醒依赖该设备领取的文件可能受影响。未实现安全对象记录前，不提供删除整个目录或自动清空功能。

自动策略继续保持现有传输可用性。显式选择仅经网盘后，账号失效时保留待发文件并解释恢复方法，不自动改走应用公网中转；文字消息照常发送。设备私聊与共享会话身份独立于网盘账号；更换账号不得替换会话身份。

## 共享架构

Surface 只处理交互、显示状态和调用模块命令。模块负责账号生命周期、运行时与任务调度；Core 负责提供方及 OpenList 接口。账号非敏感信息持久化，凭据经已有平台 SecretStore 保存，不写进偏好、消息或日志。嵌入 OpenList 的私有运行数据也保存驱动凭据，因此其数据目录必须保持原有本机访问边界，不能作为普通偏好或可分享备份导出。

提供方授权能力按真实接口声明。需要应用身份或回调配置时，缺少配置的状态必须可解释，不能以要求用户复制 Cookie 或开发者令牌作为普通添加流程。接收消息只授予指定文件的领取能力，不包含整盘账号凭据。

## 验收

模块测试覆盖账号状态转换、取消授权、错误恢复、凭据脱敏、旧配置保留、暂停和默认选择及仅网盘策略。Surface 验证空状态、可用、授权失败、暂停和断开交互，检查窄屏、键盘及返回行为。

Windows 使用完整安装布局的 Dev overlay 实际启动。Android 在独立 QA 用户验证，结束后恢复原用户及其草稿。真实提供方验收必须完成授权、创建目录、上传和另一设备领取；仅通过测试或本机 OpenList 不等于网盘验收。

## 本轮已验证的边界

真实夸克和百度账号均已通过独立发送模块与接收模块的共享附件验证：发送模块通过嵌入 OpenList 上传 1 MiB 文件，无网盘账号的接收模块经候选中转服务自动领取，内容一致并写入接收回执。每个提供方分别验证了两个附件。中转服务只保存消息和指定文件的领取元数据，没有附件正文副本。仅经网盘时文字仍正常发送；暂停账号后附件保留待发，恢复后原队列自动完成。百度首次测试触发了候选服务的注册频率限制，重启该测试服务后原队列自动恢复，没有调用手动同步绕过调度。

公网服务部署后，独立模块经实际 HTTPS 中转地址完成了百度的两个 1 MiB 附件、暂停恢复和文字发送，以及夸克的一个 1 MiB 附件收发。复测修复了 Python 3.10 解析 .NET 七位小数时间戳的问题；领取期限用服务返回的时钟换算到客户端，服务端仍按原始期限检查权限。测试会话提前在本机接口注册，以避免测试注册次数消耗公网限流额度，附件传输仍全程经过实际公网 HTTPS 地址。此次百度复测改用运行实例保存的更新凭据；复用最初的测试凭据时，新建实例连接失败。

当前网盘附件通道支持共享会话，领取时发送设备必须在线。私聊附件尚未接入此通道，不能借用共享会话凭据发送。详细协议见 [CLOUD_STREAM.md](../tools/file-transfer/relay/docs/CLOUD_STREAM.md)。Windows 已用官方 Dev overlay 更新并启动，实际检查了网盘入口、百度原生二维码显示和取消返回。本轮真实收发使用独立模块，不等同于 Windows 或 Android 界面中的账号收发验收。

Android 夸克登录使用提供方的桌面网页客户端，并在手机上整体缩放；其移动网页只展示下载入口，无法完成账号连接。网页保留扫码及手机号登录入口。登录结果在原生窗口完成销毁后交付给 MPT，避免返回时弹层被隐藏窗口的零尺寸布局清空。

Android 百度授权请求使用官方 `display=mobile` 展示方式，保留提供方请求中的回调、权限和其他参数；WebView 同时支持网页的 viewport 和整体缩放，避免桌面授权页裁切。

运行时事件泵只为当前平台有兼容入口、且已注册对应传输实现的模块建立订阅。没有入口或传输实现的目录项不会通过轮询变为可运行，因此不启动每秒重试任务；启用模块和目录刷新时仍会重新判断并启动可运行模块。兼容模块的真实故障重试和正常事件接收保持原有行为。

Android 与 macOS 的主机连接监视在连接健康时等待事件；事件流断开会请求检查，离线恢复仍保留重试。Android 使用进程内 HostControl，不再每五秒查询健康状态。

Android 启动进度条在切换到主界面前结束不确定进度动画，并在启动视图脱离可视树时停止计时器和动画。仅替换内容会留下 Fluent 的两个动画时钟订阅，持续触发 16 毫秒的动画调度。测试使用真实 Fluent 模板，确认主界面显示后这些订阅归零。

Android CoreCLR 构建关闭后台分层编译，使用首次调用时的常规 JIT。真机采样发现空闲时仍有分层编译线程持续占用 CPU，因此将编译成本集中到首次执行，并分别测量启动和稳定闲置；后台接收、故障重连和工具生命周期不因此停用。

Android 的 `AndroidDispatcherClock` 为固定的 Avalonia 12.0.5 提供时钟兼容处理。在 Android 平台调度器安装前，Avalonia 已创建自己的时钟；两个不同的时间基准会让未来的定时任务被反复立即唤醒。手机主视图创建前将截止时间计算绑定到 Android 调度器的同一时钟。兼容处理集中在一个类中，使用框架内部字段；升级 Avalonia 时必须复核该接口及延迟任务测试。它不关闭后台功能，也不改变任务间隔。

Android 开发包已在真实 ARM64 Pixel 4a 上完成共享会话文字和附件双向收发；接收路径包含真实夸克网盘附件，发送路径包含系统文件选择器。收发完成状态与实际字节内容均已核对。此项接收端是手机，另一端是独立 Linux 模块实例，不代表 Windows 界面验收。真实手机上的完整账号授权、外部文件打开与剩余闲置开销仍需分别验收。macOS 完整安装与功耗验收、各提供方的真实授权和收发分别记录，不用其他平台结果代替。
