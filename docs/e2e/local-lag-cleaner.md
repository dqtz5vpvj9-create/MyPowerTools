# 本机卡顿专清流程验收

执行：`npx e2e run tests/e2e/local-lag-cleaner.e2e.ts --output .e2e/tools/local-lag-cleaner`。
先按仓库 `scripts/prepare-e2e.ps1` 构建当前 Debug 测试与 Runtime。该套件使用 e2e 工具目标驱动真实 .NET Runtime、MPT 主机和行为回归，桌面 Avalonia 控件操作仍需独立验收。

| 用户流程 | 自动化验证 | 测试层 |
|---|---|---|
| 工具发现和 Runtime 健康状态 | MPT 加载临时工具清单，真实 stdio 请求与健康返回 | 主机与进程集成 |
| 首次进入和撤销空态 | 无历史结果、无待清理计划、空恢复记录 | 真实 Runtime |
| 快速/深度检查 | 实际 Windows 系统采样，JSON/Markdown/历史报告导出、路径约束 | 真实 Runtime |
| 六种清理方案 | MCP、WeFlow、分发优化、NVIDIA、远程桌面、Windows Search 生成方案；无合格进程时拒绝 MCP/WeFlow | 真实 Runtime |
| 清理确认 | 错误令牌、错误计划 ID、错误动作和缺少服务重启确认保留待处理计划 | 真实 Runtime |
| 提权前校验 | 四种服务计划的过期、令牌、身份、动作、重启/断连确认校验；计划保持未领取 | 独立 .NET 回归 |
| 清理并发和过期 | 并发写入完整计划、令牌期限、PID 身份变化时拒绝执行并消费领取记录 | .NET 行为回归 |
| 临时文件处理 | 临时隔离目录中仅删除过期且可独占打开的 .tmp/.temp；近期文件、其他扩展名、锁定文件保留 | 真正文件操作 |
| 硬缺页诊断 | 真实进程身份采集、PID 复用与计数器重置过滤 | 系统采集与行为回归 |
| 自动内存/内核检查 | 各执行三轮真实采样，结果持久化后重新读取，确认没有优先级恢复记录 | 真实 Runtime |
| 分页、趋势与健康分 | 孤立峰值、相关压力、缺失采样、开机身份、空闲状态、域分数上限 | 算法行为回归 |
| 查看对应处理方案 | 发现到对应方案和工具命令的导航 | ViewModel 命令流程 |
| 报告和恢复说明 | 采样完整度、读写指标、句柄类型、逐项处理步骤与恢复说明、敏感信息排除 | 序列化与报告行为回归 |

每次真实 Runtime 测试以唯一临时目录设置 `MPT_DATA_ROOT` 并清理该目录；进程计划只提交无效确认请求，服务重启和用户进程终止均未执行。编译输出 Runtime 作为隔离测试对象；产品桌面验证按开发版 overlay 流程执行。

此次发现并修复的缺陷：服务清理请求在检查计划 ID、动作、令牌、有效期和显式确认前进入管理员 Broker。现在 Runtime 先用核心同一套校验检查用户请求，通过后请求提权；真正执行仍在领取锁内再次校验。无效请求保持待执行计划，返回 `plan.rejected`。

覆盖缺口：

- Avalonia 页面真实点击、窗口显示/恢复、取消按钮状态，e2e 当前 browser/mobile 引擎无法直接控制 Windows 原生窗口。
- 管理员 UAC 同意/拒绝、Broker 服务重启成功/失败、远程桌面实际断连，需要隔离 Windows 虚拟机及合成服务验收。
- `care.all/background/storage` 会清理真实 LocalAppData/Temp 或改变现有后台程序优先级；本套件仅验证隔离文件清理与空恢复记录，完整三轮自动处置和真实优先级撤销仍待隔离环境验证。
- 管理员全机文件句柄归因、系统工具启动、真实驱动泄漏修复需要隔离机器验收。

报告位于 `.e2e/tools/local-lag-cleaner/report.json`、`junit.xml` 和 `summary.md`。执行结果以这些报告为准；覆盖缺口保持为待验收流程。

本次验证结果：9/9 e2e 场景通过，耗时 207.88 秒，退出码 0；其中调用的四组 .NET 回归分别为 2、8、3、33 个，合计 46 次全部执行并通过。执行环境为 Windows、Debug 当前仓库构建；生产服务重启和进程结束未执行。
