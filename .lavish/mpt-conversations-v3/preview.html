流程与实现边界

前台只有会话，后台负责抵达。

这是下一版流程提案。网页中的发送、收件与网络状态均为模拟，不会传输你的文件。

01 / 会话

一台设备，一段私聊

会话列表显示最近消息、未读和未发送草稿。通讯录管理已添加设备；点设备先看名片，再进入私聊。每段会话独立保存消息、附件、草稿与滚动位置。

02 / 共享

一个明确范围的公屏

“文件传输助手”置顶，只有明确加入的设备可见，不是整个网络都能读。消息标注来自哪台设备；详情显示逐设备接收回执。添加联系人不自动加入共享会话。

03 / 发送

离线也能点发送

选文件只是加入待发区，点击发送才入队。断网显示“等待网络”，恢复后自动继续；中转保存显示“已暂存”，取得接收回执才显示“已送达”。失败留在原消息上，可重试或取消。

04 / 传输

路径属于每一次传输

优先尝试可用直连，包括局域网与 Tailscale 点对点；不可达时自动用已授权中转。默认公网 proxy.lixinrui000.cn 兜底。用户明确限定私有网盘时保留该选择，不静默换公网。

05 / 网盘

省服务器流量，按需下载

OpenList 接入的网盘可保存离线文件，减少自建代理转发的流量；不承诺凭空减少手机流量。移动网络下大文件可只收通知，点按后下载；文字仍正常送达。

06 / 迁移

保留底座，重新组织界面

沿用现有模块、命令、存储、队列、权限和事件。私聊按双方稳定设备 ID 分组，共享会话按会话 ID 分组。旧记录能确定归属才迁移，含糊记录保留在“历史记录”，不复制成重复消息。

可直接试：通讯录 → 添加设备 → 预览确认 → 私聊；会话 → 文件传输助手 → 成员；输入文字或添加示例文件 → 发送 → 点击状态看详情。顶部“模拟断网”可查看排队和恢复。
设计来源：用户指定的微信式导航 + MPT 现有蓝色、浅色背景与圆角组件。此稿不改已安装客户端。
