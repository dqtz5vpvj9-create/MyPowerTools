# 文件助手 V3：会话与通讯录提案

本稿响应2026-09-29用户提出的模型：设备之间私聊，文件传输助手为已加入设备的共享公屏，网络路径属于后台实现。原型沿用MPT蓝色与浅色基调，导航采用用户指定的微信式会话列表和通讯录。此稿不修改安装版或生产数据。

## 页面与流程

- 桌面：文件助手工具内的会话/通讯录导航、列表、聊天区域。手机：列表 → 独立详情页 → 返回原列表；聊天期间隐藏列表底栏。
- 会话：共享会话置顶，私聊按最近消息排序；独立未读、草稿和最后消息摘要。原型时间为固定示例，真实产品使用消息时间。
- 通讯录：已配对设备稳定存在，离线不消失。添加设备 → 扫码/粘贴 → 名称、设备标识、互传权限预览 → 确认 → 名片 → 发消息。
- 私聊：接收方固定为当前会话，不在聊天里另选目标。每段会话独立持久化文字、附件、滚动位置；跨设备转发需要选会话并确认。
- 公屏：“文件传输助手”仅共享给明确加入的设备。成员入口显示范围；从通讯录邀请时再次声明历史及后续共享内容，对方确认前不授予权限。普通配对不自动加入。
- 系统分享：先选会话，再合并到该会话待发区，保留原草稿，不自动发送。选文件同样不自动发送。
- 消息：文字、文件卡片、发送设备、真实状态。点击打开或查看详情；长按/上下文菜单包含复制、转发、保存副本。原型用点击详情演示转发。
- 发送：入队 → 进度 → 中转已保存/目标已保存。共享会话的“已同步”不代表每个成员都收到，详情逐设备显示回执。界面只消费真实事件，不自己猜测完成。
- 网络：断网仍能入队，恢复自动继续；目标离线可暂存；权限错误等不可恢复错误停在原消息，提供具体原因与重试/重新连接，取消不得撤销已完成的远端保存。

## 后台与存储

沿用当前模块、命令、队列、存储、权限和事件。会话层只增加分组与读取模型；不能为了换UI另建一套传输系统。

私聊key由本机与对端稳定设备ID确定；共享key使用既有conversationId，不能仅按targetDeviceId为空就判断所有历史属于同一个公屏。收件需保留实际来源类型（配对收件箱、共享会话、直连及其作用域），不能把共享消息误归入发送设备的私聊。现有无法判明来源的消息保留到“历史记录”，不猜测、不删除、不重复发送。

后台根据每对设备当时可达性选择直连（局域网/Tailscale）或授权中转。默认公网为proxy.lixinrui000.cn；已有自定义OpenList策略保留，私有存储限制不允许静默公网上传。协议替换不得改变消息ID、授权范围、回执含义和去重规则。

网盘主要节省自建中转带宽；手机节流来自移动网络下的大文件按需下载，不承诺网盘本身消除收发流量。OpenList配置继续支持既有实例和托管安装流程；凭据与服务配置不进入普通聊天页面。

## 验收要求

同一设备有私聊与共享成员身份时，两条消息流仍严格隔离。升级保留原文件与记录；含糊历史单列。通讯录离线设备仍可发，系统分享无自动发送，转发确认目标，草稿跨会话不串，公屏逐设备回执准确。Windows/macOS双栏与Android单栏都可完成全部主要操作。接收端落盘和发送端页面更新必须成对验证，尤其最后一条图片自动收尾。

## 原型范围

app.js提供示例数据、模拟发送/断网恢复、设备添加、成员邀请、系统分享选会话、草稿隔离和转发。文件选择只读取浏览器提供的名称与大小，不读取/上传内容；扫码、授权、系统查看器为明确标注的模拟入口。原型未实现真实存储、配对或后端传输。
