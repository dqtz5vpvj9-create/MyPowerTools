# MPT 网盘体验 v4

这是可点击的产品原型，不是已经接入真实网盘的客户端。只修改本目录；不替换现有会话原型或生产界面。登录、账号、空间、目录、文件和传输状态均为示例，页面不会采集密码、Cookie 或 Token，也不会上传文件。演示偏好保存在浏览器本地，可用右上方「重置演示」恢复。

打开 [index.html](./index.html)。默认展示已连接账号；顶部可切换「首次连接 / 正常 / 需重新登录 / 空间不足」，以及桌面或手机预览。窄屏浏览器自动使用手机布局。原型沿用已批准的 `mpt-conversations-v3` 白、灰、蓝样式和 MPT Shell 的导航语义。

## 用户操作

网盘的作用是让**这台设备发送文件时，可以使用自己的网盘中转**。接收方领取消息中的指定文件，不必登录发送方的网盘。

1. 在「我的网盘」添加账号，选择品牌，在网盘自己的页面完成登录和授权。
2. MPT 在后台准备专用文件夹、确认读写能力；成功后显示账号和保存位置，回到会话即可发送。
3. 默认使用「自动」：优先直连，需要中转时使用默认网盘；网盘不可用时，可以使用应用中转。添加失败不影响已有传输方式。
4. 用户主动选择「仅经网盘」后，网盘不可用时保留待发内容，不切到公网应用中转，也不偷偷改用直连。恢复账号、释放空间或明确修改策略后继续。

账号管理与会话分开。主界面只保留账号状态、默认中转盘和三项偏好。后台组件不出现在正常流程中；「帮助与诊断」才提供低频状态摘要。

目录通过选择器选择，MPT 使用选定位置下的专用文件夹。保持默认无需操作；修改位置只影响新文件，已有文件不移动。登录过期后重新授权保留原目录和策略。空间不足时可清理已全部接收的 MPT 副本，或改用另一个账号。

暂停不退出账号；断开移除本机登录信息，两者默认都不删除网盘文件。尚未领取的文件若依赖发送端刷新链接或代理，暂停或断开会影响领取，确认层会提醒。清理只覆盖 MPT 创建并记录的对象，默认手动确认；自动清理从全部接收后开始计时，尚未全部接收的内容保留。接收端已经下载的本地副本不受影响。

原型授权确认页明确让用户查看提供方实际申请的权限。MPT 的「只用于专用文件夹」是应用行为约束；若提供方的令牌权限更广，正式授权前必须如实展示，不能标成提供方已提供文件夹级授权。

## 保留现有架构的实现边界

沿用共享 Shell、工具 Surface、FileTransfer 模块和 Core 存储。现有 `OpenListRuntime` 继续负责嵌入运行时，按需在后台启动；通过模块新增账号管理命令与提供方适配层，不让 UI 直接管理进程或写 OpenList 配置。现有手动 OpenList/WebDAV 入口可留在高级设置，不作为普通添加流程。

建议账号状态为：等待授权、准备目录、可用、登录过期、空间不足、已暂停。账号只有在授权返回、创建或选定专用目录、实际读写确认均成功后才成为可用；取消和失败不能覆盖原有可用账号。授权回调关联本次操作，切页或取消后不得误连其他账号。重新登录只替换对应账号的授权信息，保留目录与使用策略。

提供方适配层至少需要授权开始/返回、刷新授权、列目录/创建目录、上传、生成限权领取能力、查询剩余容量、删除 MPT 已记录对象。单次授权成功不代表这些能力都已经可用；驱动没有可靠容量接口时显示「空间信息暂不可用」，不能虚构剩余容量。

### 凭据和接收权限

账号登录凭据留在本机，使用 Android Keystore、Windows Credential Manager/DPAPI、macOS Keychain 对应平台能力安全保存。普通设备配对、共享会话成员资格和网盘账号授权是不同权限，不互相扩大。

发给接收方的是**指定文件的领取能力**，绑定已授权会话或接收设备、对象标识、有效期与撤销状态；不能列举整盘，也不能拿它获取账号 Cookie、刷新令牌或管理员密码。优先使用提供方真实支持的限权链接；若驱动只有广泛账号权限，MPT 必须保留凭据并通过受限文件服务交付，不把广泛 Token 放进消息。

另一台自己的设备希望无需重新配置目录时，可在已连接设备确认后接收品牌、账号显示名、专用目录等非敏感配置。若希望由原设备代为上传，应颁发明确设备范围、仅 MPT 专用内容的操作能力，并允许单独撤销；原设备离线时该模式不可用。需要另一台设备独立发送、离线运行时，应由提供方为它单独授权。首版不默认复制完整 Cookie 或刷新令牌到所有配对设备，也不以共享会话连接码代替账号授权。

### 可领取条件与清理权限

提供方允许接收端直接访问且链接有效时，接收不依赖发送设备在线；链接刷新、带账号请求头的代理或受限文件服务若由发送设备执行，则需要它在线。必须逐品牌、逐驱动验证，展示真实的等待/可领取状态，不能承诺所有品牌在发送端永久离线后仍可领取。仅经网盘策略下，不能为了离线可用性默默复制文件到应用公共中转。

现有 `OpenListSetup.cs` 创建的互传 DAV 用户不授予删除权限。清理功能应使用独立、仅本机拥有的操作路径，对照 MPT 保存的对象记录删除本工具创建的内容，不能通过扩大共享 DAV 凭据权限实现，也不能以目录名相同为由删除用户原有文件。路径选择与用户已有 `MPT` 文件夹共存，不把整个文件夹视为可清空区域。

暂停/断开时保留待发任务和已发送记录，并据实际授权撤销行为更新领取状态。删除中转副本之前，明确展示失去再次下载能力的影响。网盘能分担应用公共中转服务器的带宽；手机上传和接收仍产生网络流量，不能宣传为自动节省手机移动数据。

## 原型验证

交互检查和截图证据放在 `/mnt/cache/data-cache/mpt-cloud-v4/`，详细结果见该目录的 `verification.json`。截图由 `webshot` 生成后逐张查看，不把截图命令成功当成视觉验收。

本轮结果：7 条实际浏览器点击流程全部通过，覆盖首次添加后发送、登录失败后恢复、空间不足后清理、仅网盘暂停/恢复/断开、第二账号与偏好保存、取消授权和桌面扫码替代入口。320、390、768、1440 像素四种宽度下，9 个页面/弹层场景共 36 项横向溢出检查通过，浏览器脚本异常为 0。

已查看截图：`desktop-normal.png`、`phone-normal.png`、`phone-first.png`、`phone-login.png`、`phone-expired.png`、`phone-space.png`、`phone-cleanup.png`。桌面为 1440×1000，手机为 390×844；手机设置页纵向滚动，弹层底部操作可见。浏览器交互验证使用同目录 `verify.mjs`，这些测试证明的是网页原型行为，不是 Android 或 Windows 原生产品已经实现。

正式产品尚未实现：真实品牌认证与回调、网盘目录读写准备、密钥安全存储接线、逐品牌文件领取条件、容量查询、授权撤销与安全清理。当前原型的「已送达」和诊断状态全部为模拟，不可用于网络或账号接入验收。
